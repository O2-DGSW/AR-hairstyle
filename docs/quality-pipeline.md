# 합성 품질 파이프라인 — 화질 / 이질감 / 앞머리→이마

> 2026-09 기준. HairFastGAN 결과를 실시간 워핑에 얹을 때 "AI 텍스처" 와 이질감이
> 어디서 생기는지 실측하고 고친 기록. 숫자는 전부 `server/train/frames/0816_015751`
> (실제 웹캠 640x480, 242장) 과 그걸로 구운 뱅크에서 잰 것이다.

## 0. 먼저 — 무엇이 GAN 이고 무엇이 본인인가

실시간 화면에서 **본인 픽셀이 아닌 것은 두 군데뿐**이다.

| 영역 | 출처 | 왜 |
|---|---|---|
| 새 헤어 | GAN 결과에서 오려낸 에셋 (`cls==13`) | 각도별 뱅크 7칸 |
| 지운 앞머리 자리 (이마/눈썹) | GAN 결과의 얼굴 패치 (`cls 1~12`, `asset.face`) | 관측된 적 없는 이마를 채울 유일한 근거 |

눈/코/입/볼은 항상 실제 프레임이다. 그런데도 얼굴이 "AI 처럼" 보였던 이유가
따로 있었다 (§3).

## 1. 진단 — 이질감의 실제 원인 (실측)

기존 파이프라인의 정면 프레임 합성본을 확대해 보면 네 가지가 한 번에 보였다.

1. **헤어 외곽의 밝은 테두리.** `build_from_photo` 가 스트레이트 알파(마스크 밖
   RGB 가 GAN 배경/피부색)를 만들고 3px 페더를 건다. bilinear 워핑이 경계에서
   그 배경색을 끌어와 주황/흰 띠가 됐다.
2. **헤어가 장면보다 새까맣다.** 웹캠은 플레어/역광으로 뿌옇다(프레임 휘도 2%
   분위수가 17~21 - 아무것도 진짜 검지 않다). GAN 은 노출을 "정상"으로 되돌려
   또렷한 어두운 머리를 그린다. 기존 harmonize 는 곱셈 배율뿐이라 검은 것을
   밝힐 수 없었다.
3. **이마가 평평한 살색 스티커.** 얼굴 패치가 영속화되지 않아 재시작 후에는
   평균 살색 폴백으로 돌아갔다. 패치가 있어도 GAN 이마에는 **앞머리 그림자
   얼룩**이 남는다 - Alignment 의 SEAN 인페인팅 → e4e(256) 재인코딩 경로가
   원본의 앞머리를 뭉갠 채로 이마에 남기기 때문이다(4개 각도 전부 재현).
4. **눈이 남의 눈.** 앞머리 + 안경 + 뿌연 조명에서 SegFormer 가 **눈 부위까지
   통째로 '머리'로** 분류하는 프레임이 있다(샘플 4장 중 2장). 그러면 눈이
   지워지고 GAN 얼굴 패치의 눈이 그 자리를 덮는다. 파싱 클래스 기반 눈 보호는
   이 프레임에서 아무것도 보호하지 못한다.

그 외 스케일 실측: 640x480 프레임의 눈 간격 46~53px → FFHQ 1024 정렬(눈 간격
~220px)까지 **4.4배 업스케일** → 에셋을 프레임에 얹을 때 다시 4.4배 축소.
grid_sample bilinear 는 축소에 안티에일리어싱이 없다.

## 2. 고친 것

### 2.1 GAN 입력 (뱅크/촬영 시점, 오프라인)

| | 파일 | 내용 |
|---|---|---|
| 앞머리 사전 제거 | `gan_input.py`, `server.prepare_gan_input` | 눈 위 0.28D~1.3D 의 머리 픽셀을 **눈썹 위 보이는 피부색**으로 채워 GAN 에 넣는다. 원본 머리 마스크가 이마를 포함하지 않게 되어 그 자리 F 가 SEAN 이 아니라 원본의 FS 인코딩에서 온다. 정수리는 남긴다. `HEDDY_GAN_PREFILL_FOREHEAD=0` 으로 끔 |
| 선명한 프레임 선택 | `server._collect_for_bank` | 각도당 후보 `live_pick_frames`(8)장 중 얼굴 크롭 라플라시안 분산 최대 프레임. yaw 정지 판정은 상하 흔들림/초점 흔들림을 못 거른다 |
| 정렬 | `gan_worker._align_direct`, `ffhq_align` | 원본에서 한 번의 리샘플링으로 1024 정렬. 업스케일이면 bicubic. 실측: 예전 경로(cubic 업스케일 + bilinear)와 선명도 동등(hf 0.89 vs 0.87), 크롭 실패로 dlib 에 떨어지던 측면 프레임이 사라짐 |
| 수신 해상도 | `server.recv` | 처음/바뀔 때 로그 + `stats.frame_size`. 브라우저가 업링크를 몰래 낮추면 여기서 보인다 |

채움 아래 한계 0.28D 는 실측으로 정했다: 눈썹선(0.45D)에서 끊으면 그 아래
남은 앞머리 끝을 GAN 이 짙은 띠로 그린다. 0.25D 까지 내리면 띠가 거의 사라진다.

### 2.2 에셋 (뱅크 시점)

| | 파일 | 내용 |
|---|---|---|
| 추출 규칙 공유 | `asset_extract.py` | 머리 + 얼굴 패치 추출을 서버와 `train/make_asset_bank.py` 가 같은 함수로 |
| 얼굴 패치 영속화 | `hair_asset.save_asset/_read_asset` | `<name>.face.png` + json `"face"`. 로더는 `.face.png` 를 독립 에셋으로 등록하지 않는다 |
| 촬영본 | `server.compose_still` | "사진 찍기" 결과 = **본인 얼굴 위에 실시간과 같은 경로로 합성**한 것. GAN 원본(얼굴까지 재생성)은 `gan_*.png` 로 따로 |

### 2.3 실시간 합성 (`gpu_segmenter.process`, 프레임당)

| 단계 | 설정 | 내용 |
|---|---|---|
| 프리멀티플라이드 밉맵 | - | `_asset_entry`: 에셋을 알파 곱한 BGRA 로 1/2^k 안티에일리어스 피라미드에 캐시. `_warp_asset` 은 배율에 맞는 레벨(남는 축소 < 2배)에서 샘플링 → 에일리어싱과 경계 프린지 둘 다 사라짐 |
| 프레임 스케일 페더 | `edge_feather` 0.05D | 4채널을 함께 흐린 뒤 un-premultiply |
| 블랙레벨 lift | `black_match`, `black_pct` 0.01, `black_lift_max` 90 | **머리 주변**(눈 기준 3.6D×3.7D 상자 - 본인 머리/눈동자/콧구멍이 있어 항상 어두운 게 있다)의 어두운 분위수 − 에셋 머리 어두운 분위수 만큼 `x + lift·(1−x/255)` (안개 모델: 어두운 곳을 더 들어올림). 프레임 전체를 쓰면 흰 벽뿐인 또렷한 장면도 "검은 게 없다" 고 오판한다. 실측: 뿌연 프레임에서 본인 머리 휘도 ≈ 이 값(60~65) |
| 그레인 | `grain_match` 1.0 | 피부 코어(0.3D 침식, 프레임 밖은 '피부 아님' 패딩)의 3x3 잔차로 σ 추정(9/8 보정, 잔차 클리핑) → 같은 σ 의 휘도 노이즈를 헤어/얼굴 패치에 매 프레임 주입. 실측 σ 0.94~1.21 (MAD 강건 추정 0.76~0.86) |
| 얼굴 패치 저주파 정합 | `face_lf_match`, `face_lf_k` 0.5D | 패치 − box(패치) + box(실제 피부 외삽). 실제 피부 색 필드는 "지워지지 않는 피부" 만 넣은 정규화 컨볼루션이고, 창 안 피부 비율이 적을수록 보정을 서서히 줄인다(하드 임계면 이마에 띠가 생긴다). 눈썹/잔 음영은 패치 것을 남긴다 |
| 눈 보호 타원 | `protect_eye_rx/ry` 0.42/0.30 | MediaPipe 눈 2점 기준 타원을 파싱 마스크에 합침. 파서가 눈을 머리로 봐도 눈은 본인 것 |
| erase 강화 | `erase_hard_lo/hi` 0.25/0.60 | 얼굴 zone 안에서 소프트 알파를 다시 펴고 1px 팽창 - 앞머리 경계의 반투명 잔재 제거 |
| 그림자 띠 | `shadow_k` (눈 간격 50px 기준) | 얼굴 크기에 비례 |

전부 `HEDDY_*` 로 0 을 주면 꺼진다.

비용 (RTX 4070 SUPER, `bench_process`, tryon, 워밍업 후):

| | 전 | 후 |
|---|---|---|
| 640x480 | 15.4 ms | 19.4 ms |
| 1280x720 | 16.9 ms | 21.8 ms |

30fps 예산 33ms 안이다. 실측 결과 합성 헤어의 고주파 에너지는 원본 머리와
같은 수준(2.58 vs 2.47)이라 별도 선명도 정합은 넣지 않았다.

### 2.4 송출

`video_max_bitrate` 3 → 6 Mbps (시작 2.5). 720p30 에서 3 Mbps 는 픽셀당 0.11 bit 라
머리카락 고주파가 인코더에서 먼저 뭉갠다. 실제 송출량은 브라우저 REMB 가 정하므로
회선이 느리면 알아서 내려간다.

## 3. 검증 도구

```bash
cd server

# 1) 뱅크를 오프라인으로 굽는다 (서버 내리고, GAN 적재 ~60초 + 칸당 1~3초)
python train/make_asset_bank.py train/frames/0816_015751 --reference korean-layered \
    --out /tmp/bank --save-gan            # --no-prefill 로 사전 제거 끄고 비교 가능

# 2) 서버 없이 실시간 합성 경로를 그대로 돌려 프레임을 뽑는다 (SegFormer 만)
python train/render_offline.py train/frames/0816_015751 --bank /tmp/bank \
    --out /tmp/render --render 40,80,120,160,200,240
```

`render_offline` 은 서버의 프레임 루프(플레이트 누적, 포즈 + 거리 보정, 앵커
평활화, yaw EMA 뱅크 선택)를 결정적으로 재현한다. 같은 프레임의 전/후 png 를
나란히 놓고 보면 된다. 커밋 315b299 의 교훈 - 정지 지표가 움직이는 화면을
대변하지 못한다 - 은 여전히 유효하므로 마지막 판단은 실제 화면에서.

## 4. 남은 것 / 하지 않은 것

- **입력 해상도가 화질의 상한이다.** 640x480(눈 간격 50px)에서는 어떤 정렬
  커널을 써도 결과가 흐리다. 클라이언트 기본은 720p 지만 브라우저가 대역폭에
  따라 낮춰 보낼 수 있다 - 로그의 "수신 해상도" 를 확인할 것.
- 고개를 크게 숙여 앞머리가 **실제로** 눈을 덮는 극단 포즈에서는 보호 타원
  안에 원래 앞머리가 남는다. GAN 눈으로 바꾸는 것보다 낫다고 판단.
- 큰 yaw(±28° 이상)에서 헤어 위치/크기가 어긋나는 것은 기하(뱅크 칸 선택,
  거리 보정) 문제라 이 작업의 범위 밖이다.
- 참고사진 텍스처를 GAN 형태 안에 이식하는 구조적 대안(GAN 은 형태/저주파만)은
  시도하지 않았다. 지금 결과의 헤어 고주파는 원본 머리와 같은 수준이라 우선
  순위가 낮다.
